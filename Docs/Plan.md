# 市町村位置当てゲーム 設計書

## 1. 目的・概要

GeoGuessr対策として、日本の市町村の位置を覚えるためのWebアプリ。
市町村名が出題され、プレイヤーが日本地図上でその場所を指定する。

最大の特徴は、**都道府県名を一切表示しない**こと。都道府県を推測する段階から地図上で行わせる。

## 2. 要件

### 2.1 非機能要件

| 項目 | 内容 |
|---|---|
| 動作環境 | GitHub Pages(静的ホスティング、サーバーサイドなし) |
| 対応端末 | PC、スマートフォン(レスポンシブ) |
| 言語 | 日本語のみ |
| PWA | 対応しない |
| ダークモード | 対応しない |
| 成績の保存・表示 | 行わない(状態はセッション内のみ) |

### 2.2 ゲームルール

| 項目 | 内容 |
|---|---|
| 出題形式 | 市町村名を表示し、地図上で位置を当てる |
| 時間制限 | なし |
| 出題方式 | エンドレス。手動で次の問題へ進む |
| 回答方法 | 地図上にピンを置き「確定」ボタンで回答 |
| 判定 | 正誤のみ(ピンが正解ポリゴン内なら正解)。得点・距離点・「惜しい」判定なし |
| 不正解時 | 確定直後に正解位置を即時表示 |
| 答えを見る | 回答せずに正解を表示できるボタンを用意 |
| ヒント / スキップ | なし |
| 復習ロジック | なし |

## 3. 出題対象と表示ルール

### 3.1 出題単位

| 区分 | 出題単位 |
|---|---|
| 東京23区 | 区ごとに個別出題 |
| 政令指定都市(大阪市、横浜市など) | 市単位にまとめて出題(区は出題しない) |
| 上記以外の市 | 市単位 |
| 町・村 | 町村単位 |
| 北方領土(6村) | 出題対象に含める |

### 3.2 問題文の表示(都道府県名は常に非表示)

| 対象 | 初期表示 | 追加表示 |
|---|---|---|
| 東京23区 | 区名(例: 世田谷区) | なし(同名なし) |
| 市(同名なし) | 市名 | なし |
| 市(同名あり) | 市名 | **相対位置**(下記) |
| 町・村 | 町村名 | **「郡名を表示」ボタン**で郡名を開示 |

#### 同名の市の相対位置表示
「北か南か」は、同名の市どうしの中での相対位置として定義する(日本全体の北・南ではない)。

- 同名が2件: 「北の方」「南の方」
- 同名が3件以上: 「北から○番目(全○件)」
- 判定基準は各市ポリゴンの重心緯度
- 対象例: 府中市、伊達市、北広島市と類似名の区別が必要なケースなど。実際の対象はデータ生成時に自動抽出する

#### 郡名ボタン
- 町村の問題でのみ表示。押すまで郡名は非表示。
- 郡名は都道府県名を含まない(例: 「○○郡」のみ)。
- 郡名自体が全国で重複する場合がある。郡名の開示は都道府県の特定にはならない前提とする。
- 郡名ボタンの使用有無は、現時点では記録しない。

## 4. 絞り込み

| 項目 | 内容 |
|---|---|
| 粒度 | 8地方区分のみ(都道府県単位は不要) |
| 区分 | 北海道 / 東北 / 関東 / 中部 / 近畿 / 中国 / 四国 / 九州・沖縄 |
| 選択方式 | 複数選択可。初期状態は全国(全選択) |
| 出題プール | 選択した地方に属する市町村の全て |
| 地図表示 | 絞り込み範囲に自動ズーム(選択後の範囲に収まるよう設定) |
| 絞り込み変更 | 出題中も変更可能。変更時に出題を切り替える |

### 4.1 出題ロジック
- 絞り込み範囲内で重複なしのランダム出題。
- 全問を出し終えたら再シャッフルして継続する。
- 復習・出題頻度の調整は行わない。

## 5. 地図表示

| 項目 | 内容 |
|---|---|
| 背景 | 白地図(地名・タイルなし) |
| 都道府県境界 | 常に表示(太線) |
| 市町村境界 | 常に表示(細線) |
| 操作 | PC: ドラッグ・ホイールズーム / スマホ: ドラッグ・ピンチ |
| 離島 | 挿入図は使わず、通常のパン・ズームで表示 |
| 正解表示 | 正解ポリゴンを強調色でハイライト、ピン位置と正解の関係を示す |

### 5.1 設計上の注意点
- 全国表示では約1,700ポリゴンの境界が密集し、市町村境界が潰れて視認しづらい。ズームレベルに応じて市町村境界の線幅・透明度を変える。
- 都道府県境界が常時表示されるため、「県を絞る」手がかりは地図から得られる。この難易度設計は要件どおり。
- 都道府県境界が常時見える以上、県の位置を知っている前提で市町村を探すゲームになる。

## 6. 画面設計

### 6.1 画面構成
単一画面(SPA)。画面遷移なし。

| 領域 | 内容 |
|---|---|
| 問題表示 | 市町村名、(同名市のみ)相対位置、(町村のみ)郡名表示ボタン |
| 地図 | 白地図、ピン、正解表示 |
| 操作ボタン | 確定 / 答えを見る / 次の問題 |
| 絞り込み | 8地方のチェック(開閉式パネル) |
| 結果表示 | 正解 / 不正解の表示、正解の市町村名 |

### 6.2 レイアウト

**PC**: 地図を画面中央に大きく配置。問題表示を上部、操作ボタンを下部に配置。絞り込みは左サイドパネル。

**スマホ(縦持ち)**: 上部に問題表示、中央〜下部を地図が占める。下部に操作ボタンを固定。絞り込みはボトムシート。

### 6.3 状態遷移

```
[出題中] --ピン配置--> [ピン配置済] --確定--> [結果表示] --次へ--> [出題中]
   |                                                  ^
   +-------------------答えを見る---------------------+
```

| 状態 | 操作可否 |
|---|---|
| 出題中 | ピン配置、答えを見る、郡名表示(町村のみ)、絞り込み変更 |
| ピン配置済 | ピン再配置、確定、答えを見る |
| 結果表示 | 次の問題へ、地図の自由操作(ピン再配置は不可) |

### 6.4 スマホ固有の配慮
- ピン配置はタップで行い、ドラッグ・ピンチと区別する(移動量が閾値以下のタップのみピン配置とする)。
- 確定ボタンを別途設けることで誤タップによる誤回答を防ぐ。
- ピンを置いた後に位置を微調整できる(再タップで移動)。

## 7. データ設計

### 7.1 地図データ

| 項目 | 内容 |
|---|---|
| 出典 | 国土数値情報「行政区域データ」(N03)の最新版 |
| 形式 | TopoJSONに変換し、静的ファイルとして配置 |
| 加工 | ポリゴン簡略化、政令指定都市の区の統合(東京23区は統合しない) |
| 出典表記 | 国土数値情報の利用規約に従いアプリ内に明記する |

### 7.2 市町村データ(1件の構造)

| フィールド | 内容 |
|---|---|
| id | 全国地方公共団体コード |
| name | 表示名(例: 世田谷区、府中市、○○町) |
| type | 区 / 市 / 町 / 村 |
| gun | 郡名(町村のみ。なければ空) |
| region | 8地方区分のいずれか |
| prefecture | 都道府県(内部処理用。画面には表示しない) |
| centroidLat | 重心緯度(同名市の相対位置判定用) |
| sameNameRank | 同名の市の場合の北からの順位と総数 |
| geometry | ポリゴン(TopoJSON参照) |

### 7.3 データ生成方針
- 同名の市の抽出と相対位置の算出は、データ生成の段階で行い、静的データに埋め込む。実行時に計算しない。
- 都道府県名は内部データに持つが、UIには出力しない。

## 8. 技術選定

| 項目 | 選定 | 理由 |
|---|---|---|
| 言語 | TypeScript | 型安全。静的サイトとして出力しやすい |
| ビルド | Vite | GitHub Pagesへの静的出力が容易 |
| フレームワーク | なし | 画面が単一で状態も少ないため不要 |
| 地図描画 | D3-geo + Canvas | 約1,700ポリゴンの描画とスマホのピンチ操作で、SVGより軽量 |
| ズーム・パン | d3-zoom | マウス・タッチ両対応 |
| ピン内判定 | d3-geoのポリゴン内判定 | 回答の正誤判定に使用 |
| 保存 | なし | 成績保存を行わないため |

### 8.1 判定ロジック
- ピンの座標が正解ポリゴン内にあれば正解、なければ不正解。
- 飛び地や複数ポリゴンからなる自治体は、いずれかのポリゴン内であれば正解とする。
- 海上や自治体のない位置へのピンは不正解とする。
